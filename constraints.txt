# Frozen environment for the python 3.11 stack: the CI workflows and the LPC
# notebook venv. Used as
#
#     pip install -r requirements.txt -c constraints.txt
#
# requirements.txt says WHAT the analysis needs and is the file to edit. This
# file says exactly WHICH versions, transitive dependencies included, and is
# generated rather than hand-edited.
#
# Why it exists: requirements.txt pins direct dependencies only, so ~68
# transitive packages were resolved fresh from PyPI on every CI run and in every
# new venv -- the environment was whatever PyPI happened to serve that morning.
# On 2026-08-11 numba 0.67.0 and llvmlite 0.49.0 were released and began
# miscompiling coffea's GenPart children kernel, which turned the chain report
# red on every PR until those two were pinned by hand. This file removes that
# class of surprise: a green run stays reproducible.
#
# The Condor workers have their own condor/constraints.txt, because they run
# CMSSW's python 3.9 and resolve to a different set.
#
# To regenerate, after deliberately bumping something in requirements.txt:
#
#     python3 -m venv /tmp/freeze && source /tmp/freeze/bin/activate
#     python -m pip install --upgrade pip
#     grep -v '^xrootd' requirements.txt | pip install -r /dev/stdin
#     pip install "distributed==2025.3.0"
#     pip freeze --exclude-editable > constraints.txt   # then restore this header
#
# Run tests/chain_report.py over the result before committing the new pins.
#
# If the bump moves coffea, also update the apptainer image tag in
# sidm/tools/scaleout.py: dask workers take their coffea from that image, not
# from these files, and a split between client and workers fails at runtime.
# tests/check_worker_image.py enforces this and runs in the Pylint workflow.
